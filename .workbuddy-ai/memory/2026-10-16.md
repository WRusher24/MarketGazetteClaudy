# 2026-10-16

## Fix: "AI analyze" failing with misleading Gemini 404

**Symptom** — POST `/api/ai/analyze` returned
`Gemini gemini-2.5-flash responded 404: This model models/gemini-2.5-flash is no longer available to new users...`

**Diagnosis** (reproduced by running `next dev` + calling the endpoint, with temporary
instrumentation to log every model attempt):
- `lib/gemini.ts` `modelList()` defaulted to `['gemini-3.8-flash', 'gemini-2.5-flash']`.
- `gemini-3.8-flash` returned **429** (quota exceeded) -> code `continue`s to the fallback.
- `gemini-2.5-flash` returned **404** (retired model) -> also `continue`s -> loop ends.
- The thrown error was only `lastError` (the *last* attempt), so the transient 429 on the
  primary model was masked by a misleading 404 from the dead fallback model.
- Confirmed via `ListModels`: `gemini-3.8-flash` exists; `gemini-2.5-flash` / `gemini-2.5-flash-lite`
  are retired (404). `gemini-3.7-flash` / `gemini-3.6-flash` still answered 200 at the time.

**Fix** (only `lib/gemini.ts`):
1. `const defaults = ['gemini-3.8-flash'];` — dropped the retired `gemini-2.5-flash` fallback.
2. Replaced the single `lastError` string with an `errors: string[]` array; thrown errors now use
   `errors.join(' | ')` so a failure on the first model is no longer hidden by the last one.

Matches the upstream repo's fix commit `06ced08 fix(ai): drop retired gemini-2.5-flash fallback
and keep every attempt's error`.

**Post-fix behaviour** — the 404 is gone; the endpoint now reports the real cause:
`Gemini gemini-3.8-flash responded 429: You exceeded your current quota...`
That 429 is an account/quota limit on the API key, not a code bug.

**Env note** — the sandbox blocks `next dev`/`next build` because Next bulk-deletes `.next`
(safe-delete guard). Workaround: temporarily add `distDir: process.env.NEXT_DIST_DIR || '.next'`
to `next.config.mjs` and run with a **fresh** dir name (`NEXT_DIST_DIR=.next-dev1 npx next dev -p 3010`).
Revert the config + tsconfig afterwards (Next rewrites tsconfig `include` and line endings).

**Repo layout note** — `MarketGazetteClaudy/MarketGazetteClaudy/` is a nested clone of
`github.com/WRusher24/MarketGazetteClaudy` (upstream). It already contains fix commits
`510aa5f` and `06ced08`; useful as a reference for intended fixes. The root is the working copy.

## Follow-up: 429 quota — added live fallback models

After the fix above, analysis still failed with `Gemini gemini-3.8-flash responded 429:
You exceeded your current quota...` — the key's free-tier quota for the full "flash" tier is exhausted.

Probed every candidate model on this key (`GET /api/probe`, temporary route, since removed):

| Model | Result |
| --- | --- |
| `gemini-3.8-flash` / `3.6-flash` / `3.5-flash` / `gemini-flash-latest` | 429 quota |
| `gemini-3.7-flash` | 503 high demand |
| `gemini-3.5-flash-lite` / `gemini-3.1-flash-lite` / `gemini-flash-lite-latest` | **200 OK** |
| `gemini-2.5-pro` / `gemini-2.5-flash-lite` | 404 retired |

**Change** (`lib/gemini.ts`, same line as before):
`const defaults = ['gemini-3.8-flash', 'gemini-3.5-flash-lite', 'gemini-3.1-flash-lite'];`
— the lite models have separate quota buckets, so the existing fallback mechanism now
actually recovers instead of dead-ending on a retired model.

**Verified** — `POST /api/ai/analyze` returns HTTP 200 with a full analyst report for both
`AAPL` and `MSFT`. `npm run typecheck` clean.

Note: the lite tier is lower quality than `3.8-flash`; the primary model is still tried first,
so quality is unaffected whenever quota is available. Consider enabling billing if the full
flash tier is needed reliably.
